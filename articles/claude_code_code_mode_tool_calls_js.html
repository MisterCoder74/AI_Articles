Claude Code Code Mode: eseguire più tool call con JavaScript

Claude Code v2.1.323 introduce la Code Mode sperimentale: Claude scrive JavaScript per orchestrare i tool. Requisiti, permessi, limiti di tempo e disattivazione, in chiave operativa.

Vivacity AI Division · Novembre 2026 · Alessandro Demontis

I. Che cos'è la Code Mode e in quale stato è disponibile

Con la release Claude Code v2.1.323, pubblicata il 12 novembre 2026, arriva la Code Mode. La funzione è sperimentale e opt-in: non è in disponibilità generale (GA) e non è attiva per impostazione predefinita. Va abilitata esplicitamente seguendo la documentazione ufficiale.

Il principio è semplice: invece di emettere i tool call uno alla volta, Claude scrive un blocco di JavaScript che li invoca. Un singolo blocco può chiamare più tool in parallelo e passare il risultato di un tool a una chiamata successiva, così da comporre operazioni in sequenza dentro un unico passaggio.

In sintesi: la Code Mode è una funzione sperimentale e opt-in di Claude Code. Non va considerata GA e va valutata come tale prima di inserirla in flussi di lavoro stabili.

II. Come funziona e dove vedere il codice

Nella conversazione compaiono i tool call eseguiti, non il codice JavaScript che li ha generati. Chi vuole ispezionare il blocco può leggerlo nel transcript viewer, che si apre con Ctrl+O.

Questa distinzione ha un peso pratico: se la revisione di ciò che Claude ha eseguito è parte del vostro processo, il transcript viewer diventa lo strumento da consultare, perché la vista normale mostra solo le chiamate risultanti.

Dalla documentazione ufficiale: la conversazione mostra i tool call, non il codice; il codice è leggibile nel transcript viewer con Ctrl+O.

III. Requisiti e compatibilità

Per usare la Code Mode servono: versione Claude Code 2.1.323 o successiva, un abbonamento Claude oppure un account Console, la build nativa e una sessione interattiva nel terminale.

I modelli supportati sono Opus 5.5, Sonnet 5.5, Haiku 5.5 e Fable 5.2. La funzione non è disponibile via gateway, Bedrock, Claude Platform su AWS, Google Cloud Agent Platform, Microsoft Foundry, modalità non interattiva -p, Agent SDK, pannello VS Code, Desktop o sessioni cloud.

Non è compatibile con configurazioni HIPAA o Zero Data Retention. Alcune impostazioni impediscono l'avvio, fra cui API key helper, agent teams, OpenTelemetry e DISABLE_TELEMETRY. Restano inoltre indisponibili Remote Control, Claude in Chrome e computer use; non si può spostare la sessione in Desktop né avviare un fork in background.

Prima di provarla, controllare insieme versione, account, terminale nativo e impostazioni organizzative: basta un requisito incompatibile perché la modalità non si avvii.

IV. Permessi e auto mode: due livelli da non confondere

Il punto più delicato è distinguere la revisione del blocco JavaScript dai permessi sulle singole tool call. Le regole deny e ask e gli hook PreToolUse continuano ad applicarsi ai tool call generati dal codice.

In auto mode il classifier valuta il codice, non ciascun tool call; inoltre non vede i valori calcolati a runtime. Non è quindi corretto dire che ogni singola chiamata viene esaminata automaticamente dal classifier: la valutazione avviene sul blocco, mentre alcuni valori diventano noti soltanto durante l'esecuzione.

Negli altri permission mode il codice parte senza revisione del blocco, ma ogni tool call che richiede un permesso genera il prompt previsto dal modo attivo. La distinzione è operativamente importante: il controllo preventivo e quello applicato alle singole chiamate non coincidono.

Auto mode valuta il JavaScript; gli altri modi si affidano ai prompt per i tool call che richiedono permesso. Regole deny/ask e hook restano attivi.

V. Limiti di durata: foreground e background

In foreground Claude attende il completamento e il codice si ferma dopo dieci minuti. Nel conteggio rientra anche il tempo trascorso sui prompt di permesso: un'attesa di conferma consuma quindi parte del limite.

In background l'esecuzione può durare fino a due ore, ma la sessione deve essere stata avviata in auto mode o bypassPermissions. Per lavori lunghi il modo scelto all'avvio è dunque parte della configurazione, non una decisione da rimandare quando il processo è già in corso.

Per attività che richiedono conferme frequenti, tenere presente il limite foreground; per una procedura lunga e automatizzata, verificare prima i requisiti di background e i permessi accettabili per il progetto.

VI. Come disattivarla

La Code Mode si disattiva rimuovendo la variabile CLAUDE_CODE_EXPERIMENTAL_CODE_MODE oppure impostandola a 0. Un'organizzazione può imporre il valore zero tramite i managed settings.

Gli utenti già in una sessione Code Mode vi restano fino a quando escono o riavviano Claude Code. Cambiare la variabile non modifica quindi la sessione già aperta.

La valutazione operativa si riassume in tre controlli: verificare i requisiti, scegliere il permission mode conoscendo la differenza tra revisione del codice e autorizzazione dei singoli tool call, e considerare i limiti di esecuzione. La funzione è sperimentale e opt-in; la documentazione descrive con precisione le sue incompatibilità.

La configurazione non si esaurisce nell'opt-in: assicurarsi che la sessione usi la versione e l'account supportati e che la modalità di permesso sia coerente con il livello di supervisione richiesto.
